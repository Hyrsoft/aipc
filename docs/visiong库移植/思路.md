aipc 的media producer分为两个模式，simple ipc 和 visiong，其中simple ipc是纯粹的IP Camera模式，追求高清画质高帧率和低延迟（视频流管线），visiong负责AI处理与渲染（AI 推理管线），这两个模式区分开。

其中，VisionG 支持多种模型，比如 YOLOv5、YOLO11 物体识别、RetinaFace 人脸识别、PPOCR 文字识别等，VisionG 库提供这些 API（但需要自己准备模型文件和运行时环境）。AIPC 程序通过 Python 工程调用 VisionG API，进行具体的 AI 视觉逻辑，比如识别什么物体、如何画线等。

aipc 对 visiong库的调用，完全用visiong提供的python api，aipc相当于在web界面里提供了一个visiong的python编辑器，方便用户上传文件以及部署python代码。aipc不通过visiong的c++ api来进行任何初始化，只是给visiong的python代码提供一个运行和部署环境。

simple ipc 和 visiong 模式的切换，是冷切换，需要重新配置rkmpi媒体管线，重新配置硬件资源，当用户从simple ipc切换到visiong模式时，释放掉simple ipc初始化的所有硬件资源，比如vi、vpss、npu等，然后交由visiong的python代码进行操作。注意，当且仅当用户在编辑器中按下“部署”按钮时，才视为切换模式，而非一打开visiong的python编辑器就是切换模式。

注意：当前 simple ipc 和 visiong 都视为 media producer，获取视频资源后交由 VENC 进行编码，然后进行流媒体分发。VisionG 内部可能也集成了编码和流媒体分发相关 API，但 AIPC 项目对 VisionG 的调用仅限于编码之前的操作：AIPC 从 Python 代码中获取处理后的视频帧，再走统一的 VENC 编码和流媒体分发。

python编辑器：
中可以存放“工程”，预先提供几个工程（在assets中，跟随cmake安装规则安装并部署到设备），用户可以直接调用预先提供的python工程，也可以新建python工程，提供“保存”操作，保存的python工程和预先提供的工程是同一级别的，也是存放到那个目录，下次再打开，用户可以像打开预先提供的工程一样打开自己保存过的工程。

文件：
visiong的python代码需要调用很多外部文件，比如rknn和txt文件，预先提供的工程需要的文件，跟随cmake安装规则进行安装和部署到设备，如果用户上传文件，也存放到这个路径，在python编辑器旁提供改路径下文件列表预览，方便用户查看已有哪些文件，但不提供复选框来选择外部文件，调用外部文件完全由python代码负责，比如：
```python
import visiong
import aipc

MODEL = '/path/to/yolov5s.rknn'
LABELS = '/path/to/coco_80_labels_list.txt'

cam = None
det = None

def init():
    global cam, det
    cam = visiong.Camera(640, 360, format='rgb')
    cam.skip(8)
    det = visiong.NPU('yolov5', MODEL, LABELS, box=0.25, nms=0.45)

def run():
    while aipc.is_running():
        frame = cam.snapshot()
        if not frame.is_valid():
            continue
        out = frame.to_format('bgr888')
        for r in det.infer(frame, model_format='rgb'):
            x, y, w, h = r.box
            out.draw_rectangle(x, y, w, h, color=(0, 255, 0), thickness=2)
            out.draw_string(x, max(0, y - 20), f'{r.label} {r.score:.2f}', color=(0, 255, 0), scale=0.9, thickness=2)
        aipc.submit_frame(out)

def cleanup():
    global cam, det
    if cam:
        cam.release()
        cam = None
    det = None
```
在python编辑器旁提示文件存放路径，方便用户编写代码时参考。


如何集成visiong库？
3rdparty中的visiong源码仅用于参考以及借用它内部的python相关库，并不进行visiong的任何编译操作。visiong python的部署不由本项目负责（部署操作指把vsiong.py和_visiong.so放到指定路径下）。
